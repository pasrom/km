# CLAUDE.md

## About This Repository

The **<BRAIN>** is <TEAM>'s shared, **served** knowledge base: reviewed, current knowledge the team
reads directly (repo read access); an optional CI-built per-audience bundle feeds AI/RAG tools.
Personal, in-progress notes stay in each person's own brain; only accepted, reviewed knowledge is
promoted here.

## Access & contribution model

- **One writer.** Only the maintainer commits to `main`; everyone else reads. Contribute via a
  **fork PR** (the maintainer reviews and merges) or by **promoting** from your personal brain with
  `km promote`.
- **Uphill-only:** a served doc never links into a personal brain; personal brains link up to here.

## How to Contribute

Knowledge management via the `/km` skill ([km](https://github.com/pasrom/km); install the plugin
once with `/plugin marketplace add pasrom/km` and `/plugin install km@km`).

- **Promote a finished note:** `km promote <slug> <source> --folder <dir> [--type T] [--stub-source]`
- **Contribute without write access:** `/km contribute @<name>` (throwaway clone + fork PR)
- **Query:** "what do we know about X", `/km what is X`
- **Update / supersede:** "update the X document", `/km update ...`

See [CONVENTIONS.md](CONVENTIONS.md) for folder placement, frontmatter schema, naming, and the
status lifecycle. `km validate` enforces them (pre-commit + CI).

## Repository Conventions

- Every markdown file needs YAML frontmatter (`type`, `title`, `timestamp`, `author`, `status`,
  `tags`; `audience` + `language` on served docs). Use initials as `author` (e.g., `<MAINTAINER>`).
- No `inbox/` here, unsorted intake belongs in a personal brain or a draft PR.
- One idea per file, never duplicate, link instead. Never delete, set `status: obsolete` or
  `superseded`.
- The `## Documents` list in `_index.md` is generated by `km gen-index`; do not hand-edit it.
- km itself is not in this repo: CI installs it from the `pasrom/km@` version the workflows pin,
  and `/km upgrade` moves that pin. Change km's behaviour in km, not here.

## Git Workflow

Conventional Commits `type(scope): description`; the PR title carries the ticket key. Branch by
ticket key. Commit after every logical unit of work.

## Language

- Frontmatter (title/description/tags): English. Body: its declared `language`.
- Code comments: English.
